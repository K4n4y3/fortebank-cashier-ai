# Сервер и интерфейс: запуск, деплой, контракт

Репозиторий: https://github.com/K4n4y3/fortebank-cashier-ai (приватный).
ML-часть подробно описана в [ml/README.md](ml/README.md).

## 1. Что есть в репозитории

| Часть | Где | Что делает |
|---|---|---|
| **ML-модуль** — `analyze(видео) → результат по схеме ТЗ` | `ml/cashier/pipeline.py` | проверен на 39 роликах и под нагрузкой |
| **Каталог нарушений и нормативов** | `ml/cashier/violations.yaml` | 13 типов + «иное», пункты Правил НБРК № 231 и № 14; общий для модели, API и интерфейса |
| **Сервер** (FastAPI) | `app/` | API по разделу 10 ТЗ с ключом `X-API-Key`, очередь заданий, восстановление после рестарта, автоудаление старых видео |
| **Веб-интерфейс** | `web/` | загрузка, статус и место в очереди, вердикт, плеер с отметками эпизодов, карточки «что видно / почему нарушение / норматив» с кадрами, раздел «Как это работает» с типами, источниками, ограничениями и API |
| Скрипты GPU-сервера | `ml/remote/` | установка, запуск модели офлайн, (пере)запуск сервера |

**Проверено на поде через публичный адрес** (`PIPELINE=full`, 18.10.2026):
- `health` возвращает `ok` и `model_ready: true`; без ключа — 401; битый файл — 400 сразу при загрузке;
- `X-4.mov` готов за 26 с; загрузка и просмотр через интерфейс в браузере работают, видео воспроизводится;
- **5 самых длинных роликов разом — последний готов через 127 с, 10 роликов разом — через 233 с** (лимит 300 с, `WORKERS=3`);
- задание, загруженное по ключу (жюри), через открытый интерфейс не открывается (404).

## 2. Схема на GPU-сервере (RunPod, NVIDIA L40S 48 ГБ)

```
интернет ──► https://<POD_ID>-8080.proxy.runpod.net ──► FastAPI (0.0.0.0:8080)  [app/ + web/]
                                                           │ вызывает ml.cashier.pipeline.analyze()
                                                           ▼
                                                        vLLM (127.0.0.1:8000, наружу закрыт)
                                                           └─ Qwen3-VL-30B-A3B-Instruct-FP8, офлайн
```

- Публичный адрес RunPod обрывает запрос, если сервер не ответил за **100 с** — поэтому `POST /api/v1/analyze`
  сразу возвращает `job_id`, а результат забирается через `GET /api/v1/jobs/{id}`.
- Сервер должен слушать **0.0.0.0**, не 127.0.0.1, иначе прокси RunPod его не увидит.
- Под работает независимо от ноутбука: модель и сервер запущены через `nohup`. Остановить их может только
  Stop в консоли RunPod или нулевой баланс; после повторного старта пода нужно снова выполнить шаги п. 5.

## 3. Локальная разработка без GPU (режим `dummy`)

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt      # Linux/Mac: .venv/bin/python
cp .env.example .env                                          # и поменять API_KEY
.venv/Scripts/python -m uvicorn app.main:app --port 8080
```

Открыть http://127.0.0.1:8080. В режиме `PIPELINE=dummy` на любое видео возвращается одно тестовое
нарушение с настоящими кадрами из ролика — для отладки API и интерфейса.

## 4. С настоящей моделью со своего ноутбука (под включён)

1. Добавить свой SSH-ключ в аккаунт RunPod (**Settings → SSH Public Keys**) или получить доступ от владельца.
2. Пробросить порт vLLM к себе:
   ```bash
   ssh -N -L 8000:127.0.0.1:8000 root@<IP> -p <SSH_PORT> -i ~/.ssh/id_ed25519
   ```
   (`<IP>` и `<SSH_PORT>` — во вкладке **Connect → SSH over exposed TCP** пода; после перезапуска пода порт может смениться.)
3. В `.env`: `PIPELINE=full`, `VLLM_API=http://127.0.0.1:8000` — и запустить сервер как в п. 3.
   Видео читается на ноутбуке, на под уходят только кадры по SSH-туннелю.

## 5. Деплой на под (для жюри)

```bash
ssh root@<IP> -p <SSH_PORT> -i ~/.ssh/id_ed25519
cd /workspace && git clone https://github.com/K4n4y3/fortebank-cashier-ai.git forte-app   # или git pull, если уже склонирован
cd forte-app
bash ml/remote/setup_pod.sh                 # один раз: venv в /workspace, vLLM, веса модели (~3–5 мин)
bash ml/remote/serve_vllm.sh                # запуск модели офлайн (~2–3 мин до готовности)
until curl -sf 127.0.0.1:8000/v1/models; do sleep 5; done

cp .env.example .env && nano .env           # PIPELINE=full, API_KEY=<ключ для жюри>, DATA_DIR=/workspace/jobs
bash ml/remote/start_api.sh                 # (пере)запуск сервера на 0.0.0.0:8080, ждёт health
```

Проверка снаружи (с любого компьютера):

```bash
curl -s https://<POD_ID>-8080.proxy.runpod.net/api/v1/health
curl -s -X POST https://<POD_ID>-8080.proxy.runpod.net/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@X-17.mov"
curl -s https://<POD_ID>-8080.proxy.runpod.net/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

`<POD_ID>` — в карточке пода; на поде также `echo $RUNPOD_POD_ID`.
Порт **8080** должен быть в **Expose HTTP Ports** пода (он там уже есть).

## 6. Контракт

### API жюри (раздел 10 ТЗ) — `app/main.py`

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/analyze` | поле `file` (.mov), заголовок `X-API-Key` → `{"job_id", "status": "processing"}` |
| GET | `/api/v1/jobs/{job_id}` | `processing` (+ `progress`, `stage`, в т. ч. место в очереди) / `failed` (+ `error`) / `done` → `{"job_id","status","verdict","violations":[{"type","timecode_sec","description","evidence_frames":[{"timestamp_sec","image_base64"}]}]}` |
| GET | `/api/v1/health` | без ключа: `status` (`ok` / `model_unavailable`), `model_ready`, длина очереди |
| GET | `/docs` | интерактивное описание API (Swagger) |

Ошибки: без верного ключа — `401`; неподдерживаемое расширение, пустой файл, файл не читается как видео,
нет поля `file` — `400` с текстом причины; больше `MAX_UPLOAD_MB` — `413`; неизвестный `job_id` — `404`.

### API интерфейса — `/ui-api/*`

`POST /ui-api/analyze`, `GET /ui-api/jobs/{id}` (те же поля + `observation`, `why`, `sources`, `verified`,
`confidence`, `queue_position`, `elapsed_sec`), `GET /ui-api/jobs/{id}/video`, `GET /ui-api/types` (каталог).
Интерфейс видит **только задания, загруженные через интерфейс**: видео жюри, загруженные по ключу,
через открытый интерфейс не достать, даже зная `job_id`.

### Гарантия ответа за 5 минут

- Бюджет задания — `JOB_DEADLINE_SEC` (270 с) **от загрузки**, включая ожидание в очереди.
- Ответ модели на окно ждём не дольше остатка бюджета; если модель не ответила совсем — `failed` с ошибкой
  «VLM недоступен», а не ложный «нарушений нет».
- Повторная проверка кандидатов запускается, если осталось больше 20 с; не успевшие проверку кандидаты
  отдаются с пометкой «без повторной проверки» (пропуск хуже лишней тревоги).
- После рестарта сервера незавершённые задания снова ставятся в очередь.

### Вызов модели напрямую

```python
from ml.cashier.pipeline import Config, analyze

r = analyze("/path/input.mov",
            Config(api="http://127.0.0.1:8000", deadline_sec=240),
            progress=lambda frac, stage: ...)      # 0..1 и подпись этапа — для полосы прогресса
r["verdict"], r["violations"]     # ← отдаётся жюри как есть
r["details"]                      # по тому же индексу: type_id, confidence, observation, sources[], verified — для интерфейса
r["timing"]                       # время этапов — для логов
```

- Функция блокирующая (5–30 с на ролик); сервер вызывает её в `WORKERS` потоках, vLLM сам объединяет запросы.
- Если модель недоступна — `RuntimeError("VLM недоступен ...")`; если видео не открывается — `ValueError`.
- Зависимости ML-модуля для сервера — только `opencv-python-headless`, `numpy`, `pyyaml` (torch не нужен:
  модель работает внутри vLLM).

## 7. Переменные окружения (`.env`, в git не попадает)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `API_KEY` | — | ключ жюри; сгенерировать: `python -c "import secrets; print(secrets.token_urlsafe(24))"` |
| `PIPELINE` | `full` | `full` — модель, `dummy` — заглушка |
| `VLLM_API` / `VLLM_MODEL` | `http://127.0.0.1:8000` / `Qwen/Qwen3-VL-30B-A3B-Instruct-FP8` | где модель |
| `WORKERS` | `1` (в примере и на поде `3`) | сколько роликов обрабатывается параллельно, остальные ждут в очереди |
| `JOB_DEADLINE_SEC` | `270` | бюджет на ролик от загрузки |
| `DATA_DIR` | `./data` | куда сохраняются загруженные видео и результаты |
| `RETENTION_HOURS` | `72` | через сколько часов после завершения удалять видео и результат; `0` — не удалять |
| `UI_OPEN` | `1` | интерфейс без ключа (FAQ 27); при `0` интерфейс требует `?key=<API_KEY>` |
| `MAX_UPLOAD_MB` | `200` | максимальный размер файла |

## 8. Правила, которые нельзя нарушать

- **Тестовые видео жюри** (лежат в `DATA_DIR`) нельзя использовать для обучения, публиковать, передавать
  третьим лицам и показывать любым внешним ИИ-сервисам (р. 10 ТЗ).
- Никаких облачных AI-API в обработке (р. 7) — всё уже работает внутри сервиса.
- Ключ жюри и адрес/порт SSH пода — не в git.
- После хакатона удалить данные: под (Terminate), `DATA_DIR`, `dataset/`.
